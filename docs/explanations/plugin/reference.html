The freya launcher

One self-locating entry point. It resolves the suite from its own location, looks the command up in a checked-in manifest, and runs the target with sys.executable — so nothing in the skill layer names a path or an interpreter. Why →

Enforced in both directions: a test fails if a manifest entry points at a missing script, and another fails if a script with a __main__ block isn't registered. Mind the one-character distinction — freya code-graph (space) is a CLI command; freya-code-graph (hyphen) is a skill name.

Security scan modes

CommandRoundsLensesWhen
freya security scan --yes13full assessment, on request — paid, spawns headless agent workers
freya security audit --yesup to 53on demand, pre-release — paid, and the expensive one
no driver — freya-codebase-security-scan update—in-loopwhat wrap-up runs: git-diff scoped, main loop, spends nothing

Both driver modes cost real money, so both confirm before spending unless --yes is passed — and an agent shell has no tty to answer the prompt with, which is why the skill's prescribed invocations carry --yes and move the money gate into the conversation instead. wrap-up never reaches the driver at all: its security step is the skill's update mode, scoped to a git diff and its blast radius, and that stays true on the first run of a project as well as the fiftieth.

Read the exit code before the findings

ExitMeaning
0Complete — the result is the whole result.
3Incomplete — the call ceiling stopped the run early, some tasks got no usable answer, or discovery found more than --max-findings and discarded the rest. The banner names how many. Findings are kept; coverage was truncated. Never described as clean.
2Failed — bad project path, no usable answers, the context call failed, or the ceiling is too low to verify even one finding. No report is written.
4Declined — confirmation was refused, or there was no tty and no --yes. Nothing ran and nothing was spent. Re-run with --yes; do not fall back to the in-loop scan.
1No agent CLI on PATH — this and nothing else. Only here is the in-loop fallback correct.

An empty result with exit 0 means clean; an empty result with any other exit code means the scan did not run. The driver refuses to exit 0 when no task got a usable answer, precisely so a broken run can't be mistaken for a clean codebase. 4 exists because 1 used to mean three things at once, and the reading that sends an agent back to the prose fan-out is the one thing it must never be guessed at. --max-calls (default 200 attempts) is the single cost knob and --max-findings is derived from it; set it too low and the driver refuses to start (exit 2) rather than run a scan whose only possible output is a false clean. --concurrency sets the pool width; --dry-run prints the plan and spends nothing. --agent and --model must be passed together or not at all — the two CLIs' model vocabularies don't overlap.

Security finding statuses

The prose report uses eight statuses; the machine-readable findings.json collapses them to three (open / resolved / intentional):

Prose statusfindings.json
CONFIRMED · MITIGATED · NEEDS REVIEW · PERSISTENT · REGRESSEDopen
RESOLVEDresolved
INTENTIONAL DESIGNintentional
FALSE POSITIVEexcluded (not in report)

Consumers treat any finding whose status is not open as not outstanding. intentional is backed by a spec_ref (a prose claim) or the stronger behavior_ref (an accepted, test-backed guarantee).

Glossary

Blast radius
A file plus everything that transitively depends on it — computed by code-graph. What a change actually reaches.
Internal edge
An import that resolved to a real project file (not external: or unresolved:). The signal for "real feature wiring."
Behavior (BEH-NNN)
A first-class, intent-bearing record of an intended behavior, linked to a test. Numbered stably, never renumbered.
Lifecycle state
proposed → confirmed → accepted (+ quarantined/deprecated). Trust is the state; only accepted gates.
Adapter
How a behavior links to a test — a Gherkin scaffold (writes a skeleton .feature) or a native link to an existing test.
Locator
The address of a behavior's test, e.g. path#scenario-slug or path::node.
Entry
The route/handler file an integration behavior drives; its code-graph closure is the static coverage.
Fingerprint
The TEST → CODE record of which files a behavior's test exercised, with a coverage value and confidence.
Certainty
A 0–100 confidence score on an inferred spec. A heuristic, not the trust signal for executable behavior.
INTENT-NNN
A declared-intent record authorizing a change to an accepted behavior's test (governance G1).
ADR
Architecture Decision Record — a cross-cutting decision in decisions/. Outranks a spec, below a principle.
Principle
A project-wide rule in principles.md — the constitution, highest authority.
Resolution log
An append-only JSONL recording how a resolve-to-proceed finding was settled, so it isn't re-litigated.
Two-commit pattern
Code changes in one commit, generated artifacts in a second — clean history, stable references.
Store
The git checkout the skills are symlinked from. There's no separate installed copy, so the checkout is what freya update fast-forwards.
Launcher
bin/freya — the one entry point that resolves the suite's location and the Python interpreter, so no SKILL.md names either.
Conformance rule (R1–R13)
A check over the skill layer that fails the build on host-specific prose, an unregistered command, a Claude-only path, a frontmatter value outside the Agent Skills spec's keys, grammar or length limits, or fan-out language with no portability clause.
Driver-owned fan-out
Parallel work scheduled by our Python worker pool rather than requested of the agent in prose — so whether it happened is a fact, not a claim.
Validate-on-hit
wrap-up surfacing the proposed/confirmed behaviors a change touched (and uncovered code) — advisory, skippable.
Never-synced guard
wrap-up's refusal to let incremental update silently full-generate on a project that was never synced.
