portability · phase 4b · 31 Jul 2026

A Claude-only runtime owned the loop and called our logic. Now our logic owns the loop.

The audit mode ran on 143 lines of JavaScript executed by Claude's Workflow tool — a whole orchestration runtime with no equivalent anywhere else. It was the fourth Claude surface, found by a review pass rather than by the original design, and it was the largest single piece of work in the track.

The inversion

Everything turns on one change of direction.

Before

The Workflow runtime owns the loop, the concurrency and the retries. It calls our logic at the points it chooses.

Consequence: the mode exists only where that runtime exists. It cannot be unit-tested without it either.

After

Our Python owns the loop. It calls whichever agent CLI is installed as a headless worker, through one injected ask callable.

Consequence: runs anywhere Python does, and every test runs offline for free.

That injected ask is the whole trick. The engine never imports an agent, never spawns a process, never knows which host it is on — it calls a function. In production that function shells out to claude or copilot; in tests it is three lines returning canned JSON. 151 tests on the audit driver today, none of which spends a cent.

Four modules

audit.py406CLI, bounded worker pool, budget guard, degradation — and, since phase 7, the mode presets.

116 lines is the entire per-agent surface. Adding a third host means writing an argv builder and a stdout parser; everything else is already portable.

The read-only boundary, and why it is an allowlist

The design spike established that GitHub's "deny beats allow" applies to the write tool, not to writes performed through the shell: --allow-all-tools --deny-tool=write let a worker create a file with a shell redirect. Only an explicit allowlist that excludes the shell held.

So every argv here is an allowlist, never a blanket grant — and build_argv refuses to emit a blanket permission flag even if one is smuggled in through the prompt. Both adapters return through that guard, and make_ask is the only place a subprocess is spawned, so there is no bypass path.

Deleted, not bypassed

The JavaScript was removed, and every conformance exemption that existed to tolerate it went with it. That is the difference between a port and a parallel implementation: if the old path still exists, it is still the one that gets maintained.

The removal also flushed out a rule defect. R4 forbids agent-specific tool names, and its pattern matched "Workflow tool" — but the retired engine was referred to as "Workflow-powered" at least as often, and every one of those slipped through. The rule was widened to the whole Workflow[- ](tool|powered|engine|script|runtime|file) family, case-sensitive on the capital W so ordinary prose like "wrap-up workflow" stays legal.

The review it skipped, and what that cost

Phase 4b was the only phase that went in without a whole-phase review. The case for going back was that a silent defect here is the most expensive kind — it drives paid agent CLIs holding tool permissions, and it changed security-finding logic. That turned out to be right, though not where anyone expected.

The engine was clean

Every constant, the dedup key, the vote arithmetic and the disposition ladder survived scrutiny — exactly as the six mutation checks had claimed. The port itself was faithful.

Finding 1 is the whole track's lesson in miniature

An unplugged smoke detector finds no fire. A security tool that cannot tell "nothing is wrong" from "nothing answered" is worse than no tool, because it produces a document asserting safety. Phase 6 then found the shape between total success and total failure — 22 of 27 calls failing, three findings, reported exactly like a complete audit — and closed that too.

Two deliberate divergences from the original

A faithful port is not a transliteration. Two behaviours were changed on purpose, and both are documented in the code rather than left for someone to discover:

Zero verdicts is not a refutation

The JavaScript reached upheld == 0 when every skeptic call failed and dropped the finding. That is a silent delete on error. The rule is that only a unanimous refutation drops a finding, so no-information now yields needs-review.

Deduping within a round

The JS filtered a whole round against seen before adding anything, so two finders reporting the same issue in the same round both survived. Keys are added as they are seen now, so an intra-round duplicate collapses like a cross-round one.
