The largest mechanical change, and the one most likely to break what worked.

Ten SKILL.md files named Claude constructs in hundreds of places. Rewriting them by hand is the kind of job that finishes at 95% and stays there. So the finish line was built first — a conformance checker that started red against the real tree, and was driven green by the rewrite.

Red first, then green

bin/check_skill_conformance.py was written before a single rewrite. Run against the tree on day one it failed loudly, and every rewrite task existed to move it toward zero.

Why this order matters more than it sounds

A find-and-replace pass has no natural end. You stop when you stop seeing hits, which is exactly when the remaining hits are the ones your search missed. A checker inverts that: the job is done when a program says so, and every miss it catches becomes a permanent rule rather than a one-off correction.

Seven rules existed by the end of the phase. Six more arrived later — R8 in phase 3, R9 in phase 4, R10 in phase 6, and R11–R13 out of this branch's review — and none of them is decorative, because each was added red, against a real violation.

The checker also scans skills/**/*.py, not just markdown, which was added mid-phase after a Python file was found writing a Claude-only command into generated output — a class of regression that markdown-only scanning could never have caught.

A one-character hazard

The rewrite creates two names that differ by a single character and mean entirely different things:

FormIs
freya code-graph (space)a CLI invocation — the launcher runs a script
freya-code-graph (hyphen)a skill name — the agent loads instructions

Rule R3 exists for exactly this: it validates every freya <word> found in a code span against the command manifest, so a hyphen-for-space typo becomes a gate failure rather than a command that silently does not exist. The phase's own final review found several of these; they were fixed and the rule kept them out afterwards.

Nine findings at the end

The phase's final review produced nine independent findings — and the interesting thing is how few of them were the rewrite itself getting a substitution wrong.

Prose that described the old world

Comments and documentation still explaining how the previous invocation worked. Correct code, stale explanation — invisible to any grep for the construct itself, because the construct was gone.

A test that was wrong about installs

Skill-availability prose asserting exact registered names, which is wrong under a marketplace-plugin install where the names are namespaced. A correct-looking check that fails for users who installed the normal way.

The response was not just to fix them. R6, R7, and an extension of R1 to the unbraced $CLAUDE_PLUGIN_ROOT form all landed in the same commit — each new rule mutation-tested, meaning the guard was broken on purpose to confirm a named test fails. A fix that does not come with a way to notice its own regression is half a fix.

What it cost

16 commits

Six doing the rewrite, and seven amending the plan while it ran — including "Task 2 had four prose sites, not one" and a resolved contradiction about the compatibility: line.

Claude never broke

The constraint throughout: the working Claude setup keeps working at every commit. Substitutions were chosen so both hosts resolve them, rather than swapping one host's dialect for another's.
