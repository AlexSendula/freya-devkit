The plan said rewrite files at install time. The specification said you can't.

This is the phase where reading the spec before writing the code saved the architecture. One sentence made the planned installer impossible — and the replacement turned out to be smaller, safer, and to give freya update away for free two phases later.

The sentence

agentskills.io/specification

The name field "Must match the parent directory name." Claude Code's own documentation says it from the other side: "The directory name becomes the command you type."

The design had the installer applying a freya- prefix at install time — to the directory and to the name: field inside each SKILL.md. Installation is symlinking, so a link from ~/.claude/skills/freya-code-graph to <store>/skills/code-graph produces a file saying name: code-graph inside a directory called freya-code-graph. That is a spec violation, and validators reject it.

You cannot fix it by rewriting the file, because there is only one file and every agent shares it through the link. The design was not slightly wrong; it could not be built.

Planned

Repo keeps skills/code-graph/. The installer prefixes at install time.

Fails: requires rewriting a shared file, or shipping an invalid skill.

Built instead

The repo renames to skills/freya-code-graph/, name: and all. The installer becomes a pure symlink.

Bonus: freya update becomes little more than a git pull — symlinks propagate on their own.

The rename touched ten directories, ten name: fields, fifteen manifest paths, and ten hard-coded sibling paths across five scripts. A naive sweep would have found nine of those ten: one used os.path.join with a textual ../.. instead of the parents[2] idiom the others shared, and was invisible to the obvious grep. Five words for "what is already there"

An installer's real job is not creating links. It is deciding what to do about whatever is sitting at the destination — and being unable to destroy something that is not ours.

StatusWhat is thereWhat happens
okour link, pointing at this storenothing to do
foreigna link into another checkout, or a copy marked as another store'sreplaced only with --force
occupieda real file or directorynever touched. Blocks even with --force
stale-storeour link, pointing at a store that has movedreported; repaired by relink
orphan-skillour link to a skill that no longer existsreported; pruned by update

The last two arrived in phase 5, when doctor learned to see entries the installer structurally could not.

The one place a directory can be deleted

--copy mode — for Windows, where symlinks need Developer Mode — writes a .freya-install marker into each copied skill naming its source store. rmtree is reachable only for a directory carrying that marker and naming this store. A marker-less directory survives both a forced install and an uninstall, which was verified by putting a file in one and checking it was still there afterwards.

And apply_plan raises before mutating anything if any target blocks, so a half-applied install is impossible. That property was strengthened again in phase 5, after review found the launcher's own blocker could still let ten skills install and then exit non-zero.

Three entry points, one implementation

install.sh, install.ps1 and freya install are all thin bootstraps over bin/installer.py. That is deliberate: three copies of install logic is three places for a subtle divergence, and two of the three are shell scripts that nobody can unit-test.

It also means the untested Windows surface is as small as it can be — install.ps1 does interpreter discovery and delegation, nothing more. Which mattered, because for seven phases it had never run. It does now, on every push: CI drives it end to end on windows-latest, then resolves freya by name off PATH and uninstalls again. Keeping the shell thin paid off exactly as intended: on the very first run both Windows install jobs went green, while the two Windows test jobs failed 29 times. What review caught

A preview that lied

The "replaced" label was unreachable in --copy and --dry-run: copy always said "copied" even when it had just unlinked a foreign symlink, and dry-run picked its wording before it knew a replacement was involved. A preview that says "linked" when the real run would replace something is worse than no preview — it is the one output a cautious user relies on.

--dry-run that wasn't

Uninstall ignored the flag. The flag whose entire promise is "change nothing" changed things. Fixed in the same pass that made --copy installs re-runnable.

What it cost

15 commits

Three of them conformance fixes that had to land before the rename — including R8, which enforces the very name-matches-directory rule that reshaped the phase, and which had to learn to accept a YAML-quoted name.

A design claim, disproved

The phase closed by going back and correcting the portability design document itself, rather than leaving it describing an installer that was never built.
